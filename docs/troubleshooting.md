# 常见故障排障指南

客户端连不上校园网时，先按下面顺序走一遍。九成的报告在**第 1 节**就能定位；
「关于」页的 **常见错误检测** 会把这一节的大部分检查一次性跑完，并且明确标出
哪些项目因为不是管理员而**跳过**（跳过 ≠ 通过）。

> 两条贯穿全文的前提，先记住，能省掉一半弯路：
>
> 1. **校园网认证只认有线宿舍网。** 校园 WiFi（`10.66.x.x` 段）到不了认证服务器
>    `10.100.61.3:61440`，手机热点、VPN 同样到不了。插网线是硬条件。
> 2. **认证服务器不回 ICMP。** `ping 10.100.61.3` 不通是正常现象，不能据此判断
>    「网络没通」；能通与否要看挑战码有没有回来（见 2.1）。

---

## 1. 三分钟自查

按顺序问自己四个问题，每个都有对应的检查方法：

| # | 问题 | 怎么查 | 结论 |
|---|------|--------|------|
| 1 | 网线插的是不是**有线宿舍网**口？ | 「关于」页 → 常见错误检测 → 出口网卡 / 可用绑定地址 | 只有热点/VPN 的地址 = 包出不去 |
| 2 | 本机有没有拿到校园网 IP？ | 同上，看「本机出口地址」 | 不是 `10.x` 段 = 还没接入校园网 |
| 3 | 61440 端口绑上了吗？ | 「关于」页 → 端口诊断 | 报 10013 / 10048 = 见 3.1 |
| 4 | 服务端到底回了什么？ | 「日志」页 → 导出日志 | 有错误码 = 见 2.2；一行结果都没有 = 见 2.1 |

手动命令行版（标准用户即可，不需要管理员）：

```powershell
# 1. 本机 IP 与默认路由（有几条默认路由就要注意了）
Get-NetIPAddress -AddressFamily IPv4 | Select-Object InterfaceAlias,IPAddress
Get-NetRoute -DestinationPrefix 0.0.0.0/0 | Select-Object InterfaceIndex,NextHop,RouteMetric

# 2. 端口能不能绑（PowerShell 里看不到 10013，用客户端自带诊断更准）
netstat -ano | findstr 61440

# 3. 谁占着 61440
Get-NetUDPEndpoint -LocalPort 61440 -ErrorAction SilentlyContinue
```

> `Test-Connection` 在 PowerShell 5.1 的多网卡机器上会误报
> `ResourceUnavailable (Win32 错误)`，那**不是**网络故障。要测就用 `ping.exe`
> ——但见上文，服务器本来就不回 ICMP。

## 2. 认证相关

### 2.1 一直停在「获取挑战码」，日志里只有「UI: 已开始认证」

这是最常见的一类，含义很明确：**客户端把挑战包发出去了，但一个回包都没收到**，
所以既没有 IP，也没有错误码。注意它**不是密码错**——密码错会走到登录那一步并带回
错误码。

可能原因按概率排序：

1. **出口不对。** 机器上同时有热点 / VPN / 无线网卡时，Windows 按 metric 选路，
   经常把包从热点送出去。看 `Get-NetRoute -DestinationPrefix 0.0.0.0/0`：
   有多条默认路由、且优先那条不是有线网卡，就是它。断开热点/VPN 再试。
2. **接的不是有线宿舍网。** 校园 WiFi 与热点都在 `10.66.x.x` 或私网段，到不了
   `10.100.61.3`。
3. **网卡没拿到 DHCP 地址**，或者插的端口没开通。
4. **认证服务器临时故障**（换同宿舍另一台机器试一下就能区分）。

客户端一次挑战的等待上限是 **10 秒**（`recv` 超时 3 秒 × 重试），等满 10 秒还
没有回包，就说明「一个包都没回来」，不是「回包说错了」。

### 2.2 服务端返回了错误码

登录失败时服务端会给一个码，客户端把它翻译成人话。对照表（与
`drcom/protocol.py` 的 `_LOGIN_ERROR_TEXT` 一致）：

| 错误码 | 含义 | 怎么办 |
|--------|------|--------|
| `0x01` | MAC 校验失败 | 核对本机 MAC 与账号绑定的网卡是否一致 |
| `0x02` | 服务器忙 | 稍等，客户端会自己按退避重试，不用手动操作 |
| `0x03` | 密码错误 | 核对校园网密码；刚改过密码要在这里同步更新 |
| `0x04` | 余额不足 | 先充值 |
| `0x05` | 账号被冻结 | 联系网络中心 |
| `0x07` | IP 不匹配 | 网线插错端口，或网卡应改为 DHCP 自动获取 |
| `0x0B` | MAC 不匹配 | 换过网卡/主板：先自助解绑，或用旧网卡的 MAC |
| `0x14` | IP 数超限 | 该账号在线设备数已满，先注销其它设备 |
| `0x15` | 需要升级客户端 | 在本校网络下通常**等同于密码错误**，先核对密码 |
| `0x16` | IP 和 MAC 都不匹配 | 接入端口与网卡都要查 |
| `0x17` | 必须使用 DHCP | 把网卡改成「自动获得 IP 地址」 |

除 `0x02` 之外，这些码**重试都不会变**，客户端会停下来等你改配置——所以看到
状态卡在「认证失败」并且不再自动重连，是设计如此，不是卡死。

### 2.3 提示密码错误，但密码确实没错

依次排除：

- 密码里的空格/全角字符。复制粘贴时最容易带进来。
- 刚在自助服务里改过密码，但客户端里存的还是旧的——重新输一遍并保存。
- **重装系统 / 换机器后**：密码是用 Windows DPAPI 加密存的，密文绑定当前用户和
  机器，换了环境就解不开。表现是「密码明明填了却提示错误」，重输一次即可。
- 真的报 `0x03` 且密码无误：先用原版客户端登一次确认，能登说明是本客户端的配置
  问题（把导出的日志发出来）。

### 2.4 能上线，但频繁掉线

保活是每 **20 秒** 一轮（keepalive1 → keepalive2）。频繁掉线通常是：

- 网线接触不良 / 交换机端口抖动 → 看「状态」页的丢包与延迟曲线。
- 机器休眠或睡眠：休眠期间保活发不出去，服务端按超时释放会话，唤醒后要重新登录。
- 系统时间被改得很离谱（个别虚拟机环境）。
- **不是**客户端在重连：如果日志里反复出现「重连」，先看是不是 2.1 的出口问题。

## 3. 端口相关

客户端要绑定 **UDP 61440**（服务端回包就发到这个端口，换端口就收不到）。
绑定失败的错误码只有四个，含义完全不同：

### 3.1 绑定失败错误码对照

| 错误码 | 含义 | 常见原因 | 处理 |
|--------|------|----------|------|
| `10013` | 访问被拒绝 | ① 端口落在系统保留区间 ② 被安全软件独占拦截 | 见下 |
| `10048` | 端口已被占用 | 上一份客户端没退干净 / 别的程序占着 61440 | 见下 |
| `10049` | 地址不属于本机 | 「设置」里钉死的绑定地址已经失效（换了网络） | 改成自动 / 0.0.0.0 |
| `10047` | 协议族不支持 | 极少见，一般是环境异常 | 重启机器 |

**10013 的两个成因必须分开看**，因为修法完全相反：

1. **落在系统保留区间。** Windows 会把一部分端口留给「动态端口」，普通程序绑不上。
   查当前保留区间（需管理员）：
   ```powershell
   netsh int ipv4 show excludedportrange protocol=udp
   ```
   如果 61440 在某个区间里，要么把区间挪开，要么临时用管理员放开这个端口：
   ```powershell
   netsh int ipv4 set dynamicport udp start=61440 num=1
   ```
2. **被安全软件独占拦截。** 某些「网络加速」「安全卫士」会用独占方式占端口，
   表现同样是 10013。把客户端加入白名单，或临时退出该软件验证。

客户端自己会做实测而不是猜：它扫描 61440 附近 200 个端口，看失败是「孤立的一个
点」还是「一整段连续区间」，并尝试找出占用进程——「端口诊断」按钮展示的就是这份
结果。附近有连续区间被占，几乎一定是保留区间；只有 61440 单点失败，更像独占拦截。

**10048**：`Get-NetUDPEndpoint -LocalPort 61440` 看 PID，再 `tasklist /FI "PID eq <pid>"`
看是谁。最常见的其实是**上一份客户端没退干净**（见 5.2）。

### 3.2 我改了绑定端口，还能用吗

不能。服务端只往 61440 回包，把绑定端口改成别的值，结果是「挑战码永远拿不到」。
这个设置项存在是为了绕开本机端口冲突，但绕开之后通常还是登不上——优先解决冲突，
而不是改端口。

## 4. 网络环境

### 4.1 有线 / 无线 / 热点 / VPN

- **只有有线宿舍网能认证。** 校园 WiFi、手机热点、任何 VPN 都不行。
- 客户端默认把套接字绑在 `0.0.0.0`（所有网卡），由系统按路由表选出口；一旦路由
  表把热点排在前面，包就从热点走。可以在「设置」里钉死绑定地址（选有线网卡的 IP），
  客户端会同时设置 `IP_UNICAST_IF`，让 UDP 也只从这张网卡出去。
- 钉死地址的代价是**换网络就得改**（比如从宿舍换到实验室），改错了就报 10049。

### 4.2 防火墙

客户端只需要**出站 UDP**，Windows 防火墙默认放行出站，因此通常不需要加规则。
如果机器上装了第三方防火墙/安全软件，把它加入白名单即可；不需要开放任何入站端口。

> 读取防火墙配置需要管理员权限。以标准用户运行时，「常见错误检测」里这一项会
> 标为**跳过**，那是权限不足，不是防火墙没问题。

### 4.3 同一账号在别的设备上登着

报 `0x14` 就是这类。先在那台设备上注销，或者等它的会话超时释放。

## 5. 开机自启与残留进程

### 5.1 开机自启会不会注册两份？

**不会重复注册。** 计划任务的名字是固定的 `JLU-DrCOM-NG`，注册时带 `/F`
（覆盖），反复打开「开机自启」只会替换同一份任务，不会新增第二份。

但有一种**真实**的重复情形：计划任务注册失败时，客户端会退回写注册表
`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `JLU-DrCOM-NG` 值作为退路。
如果某次任务注册失败留下了这个值、之后任务又注册成功，开机时两者会各拉起一份——
第二份被单实例互斥体挡掉，表现为「开机时偶发弹窗」或「端口被占」。

现在的处理：**计划任务注册成功后会自动清掉旧的 Run 值**。已经处于这种状态的机器，
在「设置」页把开机自启关掉再打开一次即可。「常见错误检测」的「开机自启」一项也会
直接报出「计划任务与注册表 Run 值同时存在」。

手动核对（标准用户即可）：

```powershell
Get-ScheduledTask -TaskName JLU-DrCOM-NG | Select-Object State,@{n='Action';e={$_.Actions.Execute + ' ' + $_.Actions.Arguments}}
Get-ItemProperty HKCU:\Software\Microsoft\Windows\CurrentVersion\Run -Name JLU-DrCOM-NG -ErrorAction SilentlyContinue
```

第二条有输出 = 存在 Run 值，应当清掉（打开/关闭一次开机自启即可）。

### 5.2 从托盘退出后，任务管理器里还有 `JLU-DrCOM-NG.exe`

**托盘图标属于原生核心 `drcomd.exe`，不属于窗口。** 这是刻意的：关窗口不影响认证，
窗口关掉后核心继续保活。代价是——从托盘菜单点「退出」，退的是核心；窗口进程如果不
跟着退，就留下一个「没有托盘、没有核心、也认证不了」的空壳进程。

这是曾经的 bug，现在的行为：

- 从托盘退出（核心退出码 `0`，主动退出）→ 窗口进程**一并退出**，看门狗也一并收工。
- 核心**异常退出**（非 0 或崩溃）→ 客户端先尝试重启核心；重启失败才退出窗口，并且
  **不写停止标记**，所以设了看门狗时会被重新拉起。

手动清理（标准用户即可）：

```powershell
Get-Process JLU-DrCOM-NG,drcomd -ErrorAction SilentlyContinue | Select-Object Id,ProcessName,Path
Stop-Process -Name drcomd -ErrorAction SilentlyContinue
Stop-Process -Name JLU-DrCOM-NG -ErrorAction SilentlyContinue
```

注意顺序：先停核心，再停窗口。反过来窗口会以为核心崩了并尝试重启它。

### 5.3 关窗口以后认证还在吗？

在。这是设计核心：`drcomd.exe` 常驻，窗口只是面板。托盘菜单可以看状态、重连、退出。
内存占用大头在窗口进程（Flet/GUI 那一侧），关掉窗口后那部分内存还给系统。

## 6. 日志与取证

### 6.1 「导出日志」导出了什么

不是只有界面那一屏。「导出日志」会写一个文件，包含：

1. 文件头：版本、导出时间、系统信息、当前状态、最后一次错误。
2. 内存里的最近 2000 行日志。
3. 每个 `drcom-*.log*`（含轮转文件）的**末尾 4000 行**。
4. `drcomd-core.log` 的末尾——**前提是这个文件存在**。

账号在写入日志前已脱敏（形如 `20****26`），密码任何时候都不写日志。

### 6.2 为什么找不到 `drcomd-core.log`

那个文件是客户端**亲自拉起核心**时才创建的（核心的控制台输出重定向到它）。
如果打开客户端时核心已经在跑（比如开机自启先把它拉起来了），客户端只是连上去，
不会生成这个文件——**没有这个文件不代表核心有问题**。要看核心自己的输出，就从
自启或托盘那条路径复现一次。

### 6.3 反馈问题时请带上

- 导出的日志文件（脱敏过，可以放心发）。
- 「常见错误检测」的完整结果（尤其注意哪些项被标为「跳过」）。
- 网络形态：有线宿舍网 / 校园 WiFi / 热点 / VPN，以及是否多网卡。
- 是否以管理员身份运行。

## 7. 权限边界

客户端**不需要**管理员权限就能正常认证。下面这张表说明哪些操作会碰到权限墙，
遇到时不必以为是程序坏了：

| 操作 | 标准用户 | 说明 |
|------|----------|------|
| 认证、保活、关窗口 | ✅ | 全程不需要提权 |
| 绑定 UDP 61440 | ✅ | 只要不在保留区间 |
| 注册/删除开机自启计划任务 | ✅ | 当前用户的任务，无需提权 |
| 写注册表 `HKCU\...\Run` | ✅ | 当前用户 hive |
| 读系统保留端口区间 | ⚠️ 视策略 | 读不到时自检标「跳过」 |
| 读防火墙配置 | ❌ | 需要管理员；自检标「跳过」 |
| 改路由表 / 禁用网卡 | ❌ | 需要管理员，客户端不会尝试 |
| 改 `netsh int ipv4 set dynamicport` | ❌ | 需要管理员，只给出命令让你自己执行 |

设计原则：**能自己做的自己做，做不了的给出准确命令**，绝不假装做成功了。

## 8. 还是不行

按这个顺序提供信息，定位会快很多：

1. 「常见错误检测」结果（截图或复制文本）。
2. 导出的日志文件。
3. 原版客户端 `drcom.exe` 在同一台机器上能不能登上——这一步把「客户端问题」和
   「网络/账号问题」分开，价值最大。
4. 同一宿舍另一台机器能不能登——把「个人机器问题」和「楼栋网络问题」分开。
